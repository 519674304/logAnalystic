# 性能、测试与运维边界

## 性能验收目标

| 场景 | 目标 |
| --- | --- |
| 5MB 以内日志加载到可查询 | P90 <= 1s |
| 30MB 以内日志加载到可查询 | P90 <= 5s |
| 常用搜索、过滤、请求切换、时延视图切换 | P90 <= 1s |
| 峰值内存 | <= 2GB |

## 性能测试数据

需要准备固定测试数据：

- 50KB 示例日志。
- 5MB 示例日志。
- 30MB 示例日志。
- 匹配完整业务流程的 TOML。
- 期望 CSV 输出样例。

验证顺序固定为：

```text
50KB 示例日志
  -> 5MB 示例日志
  -> 30MB 示例日志
```

50KB 示例日志用于开发期快速冒烟，必须覆盖主流程和关键时延结构。5MB 和 30MB 示例日志用于性能门槛验证。

测试数据必须覆盖：

- 多文件按时间合并。
- 全局开始日志识别请求。
- 结束日志缺失时按下一次开始日志截断。
- A 应用到 B 应用的 RPC 时延。
- 主流程进入并行子进程组，再由主流程 join matcher 汇总。
- 启用和不导出的 matcher/stage。

## Rust 测试

单元测试覆盖：

- 固定格式日志解析。
- 多文件排序合并。
- 关键字和正则 matcher。
- 规则 TOML 解析。
- 规则校验职责链。
- 请求识别。
- 阶段时延计算。
- 统计聚合。
- Issue 分类和等级策略。

集成测试覆盖：

- 完整日志加载到可查询。
- 完整规则激活。
- 完整时延分析流水线。
- CSV 输出与基线对比。
- 失败时保留上一份有效状态。

## 前端测试

组件测试覆盖：

- 请求列表展示。
- 筛选条件变更。
- 时延泳道 SVG 渲染。
- 阶段 hover 和选中状态。
- 统计面板展示。
- 原始日志钻取。

端到端冒烟测试覆盖：

```text
打开应用
  -> 导入日志
  -> 激活规则
  -> 选择时间范围和场景
  -> 执行时延分析
  -> 选择某次请求
  -> 查看时延图和原始日志
  -> 导出 CSV
```

首批可以使用 Playwright 或 Tauri 端到端测试能力，Phase 5 实施计划再确定具体命令。

## 性能基准

Rust 层需要记录以下基准：

- 50KB 日志加载耗时。
- 5MB 日志加载耗时。
- 30MB 日志加载耗时。
- 基础搜索耗时。
- 正则搜索耗时。
- 请求识别耗时。
- 时延分析耗时。
- CSV 生成耗时。
- 峰值内存。

诊断日志至少记录：

- 操作名称。
- 输入规模。
- 开始时间和结束时间。
- 耗时。
- Issue 数量和等级分布。

诊断日志不记录原始日志全文。

## 正则搜索保护

正则搜索必须具备：

- 编译失败提示。
- 执行超时或步数限制。
- 超时后中止本次查询。
- 保留用户查询条件。
- 不展示不完整结果。

## 打包与运行

第一版目标是本地桌面应用：

- Windows 可执行程序。
- 本地应用数据目录保存配置。
- 不需要服务器。
- 不需要数据库服务。
- 不需要搜索服务。
- 不需要消息队列。

启动时读取本地配置文件。配置读取失败时按 Issue 流程提示，并尽量使用默认配置启动。

## 可观测性

首批可观测性只覆盖本地诊断：

- 操作耗时。
- 输入数量。
- 成功/失败状态。
- Issue 分类和等级。
- 当前数据集、规则集和分析结果版本 ID。

不做远程监控、日志上传或用户行为分析。

## 技术架构安全网

- 所有组件都有明确职责。
- 依赖方向指向领域和应用策略，不让 UI 或 Tauri 类型进入领域层。
- 日志、规则、分析三条主流程都有失败恢复策略。
- 外部中间件均有明确拒绝理由。
- 分析结果不落盘，避免过期缓存。
- Rust 注释和职责说明作为理解入口。
- 性能验收目标有对应测试数据和基准项。

# Web 后端与流式日志处理需求

> 本文因 Phase 2 原型确认「搜索为快速单查询」而修订：原「后台任务 / 任务 ID / 进度轮询 / 取消 / 过期 / 分页」语义作废，改为「单查询 + 加载态 + 滚动 + 截断」。

## 目标

让应用脱离 Tauri，改为通过本机 Web API 处理真实日志目录，并以流式方式稳定处理数 GB 日志而不整体载入内存。日志数据始终留在用户本机，不上传远端。

## 需求列表

### 运行形态

- REQ-WEB-001: 服务以独立 Rust 进程运行，仅监听回环地址 `127.0.0.1`，不暴露到局域网或公网。
- REQ-WEB-002: 服务启动不依赖 Tauri；浏览器通过 HTTP 调用本机服务完成日志分析主流程。
- REQ-WEB-003: 不引入登录、权限、多租户、数据库集群或云端日志上传。

### 工作区

- REQ-WEB-004: 前端提交一个日志目录后，服务校验目录存在性与可读性、扫描候选日志文件，创建工作区并返回摘要（文件数、总大小）。
- REQ-WEB-005: 工作区只保存目录、过滤后的文件清单和摘要，不保存完整日志文本；后续搜索与分析都引用工作区 ID。
- REQ-WEB-006: 只访问用户明确提供的目录，不主动扫描磁盘。

### 搜索

- REQ-WEB-007: 搜索是单个快速查询，同一时间只处理一个查询；发起后未出结果时前端显示加载态，不做后台任务、进度条、取消或任务 ID。
- REQ-WEB-008: 命中按时间排序返回；默认最多保留前 1000 条可展示命中，同时持续统计总匹配数，并返回 `truncated` 标志。
- REQ-WEB-009: 逐文件、固定大小缓冲区流式读取；跨块残行拼接；单行异常长时设上限并报告格式问题。
- REQ-WEB-010: 内存使用不随日志总大小线性增长；解析失败行计入跳过/格式问题统计，不中断其他文件。

### 复用能力

- REQ-WEB-011: 规则包、时延分析、CSV 导出沿用既有应用服务，通过 HTTP 端点暴露。
- REQ-WEB-012: 开发态前端（Vite，1420 端口）允许跨域调用本机服务（CORS）。

## 主流程

1. 用户在浏览器选择或输入日志目录。
2. 服务校验目录、创建工作区并返回摘要。
3. 用户发起搜索；未出结果时前端显示加载态。
4. 服务返回命中列表（≤1000，滚动查看）与截断状态。
5. 用户点击命中查看上下文。

## 关键基线

- 输入：一个日志目录（含一个或多个 `.log` / `.txt` 文件，可能包含 GB 级文件）。
- 输出：搜索结果 = `{ 命中列表（≤1000，含上下文）, truncated, total_matches, 跳过文件列表 }`。

## 验收标准

- 在未安装或未启动 Tauri 的环境中，浏览器可完成「选择目录 → 搜索 → 查看上下文」的完整流程。
- 30MB 日志在目标机器上正常处理；数 GB 日志保持固定缓冲区与有限结果集，不因整体载入内存而阻塞。
- 未出结果时显示加载态；被跳过文件可见。

## 规模烟测（smoke acceptance checks）

「有界内存」是本功能的决定性输出，不能等到集成测试才验证。用合成日志夹具在五个档位上跑主流程，断言的是**完成 + 峰值内存有界 + 结果正确**，不是 P90 耗时：

| 档位 | 夹具 | 断言 |
| --- | --- | --- |
| 小 | ~50KB | 主流程正确性基线：解析字段、搜索命中、上下文全对 |
| 中 | ~5MB | 跨块残行拼接、分块读取正确 |
| 大 | ~30MB | 固定缓冲区下峰值内存有界；1000 命中上限与 `truncated` 生效 |
| 超大 | ~500MB（合成，90% 情况的典型规模） | 不 OOM、不阻塞；加载态与结果正确 |
| 上限 | ~2GB（合成，实际上限） | 不 OOM、不阻塞；峰值内存与 500MB 档对比不线性翻倍 |

峰值内存记录：30MB、500MB、2GB 三档各记录进程峰值 RSS，确认内存不随日志大小线性翻倍；若接近线性增长即判为烟测失败。日志规模基线：90% 日志 ≤500MB，典型大文件 ≤1GB，实际上限约 2GB。

P90 耗时门槛（如 5MB≤1s、30MB≤5s）不设：那是边界性能调优，Fast Path 不投入；本烟测只验证「能完成、内存有界、结果正确」。

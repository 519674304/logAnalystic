# 业务规则集管理需求

## 目标

规则页负责管理业务规则包版本。一个规则包由 `manifest.toml` 和三层 TOML 文件组成；系统以整包为单位导入、校验和覆盖。每个版本彼此隔离；版本导入后不自动生效，用户手动把某个版本设为「生效版本」后，该版本才作为时延分析等能力的规则输入。

## 功能范围

- 第一版只支持导入一个完整 `.zip` 规则包，不支持散装单层文件或目录选择。
- `manifest.toml` 必须声明规则包版本和每个层级文件的映射。
- 当导入版本不存在时，创建该版本；当版本已存在时，以通过本地校验的整包原子覆盖该版本。
- 支持查看各版本及其内部层级树，并双击具体节点在弹窗内查看和编辑。
- 节点编辑后的完整规则包必须重新校验，校验通过后整体替换当前版本内容。
- 节点编辑只修改目标层级文件中的目标节点；原有注释、空白和未编辑项目的相对顺序必须保留。
- 不提供主页面手工新建空版本或散装层级导入入口。
- 全局同时只允许一个生效版本；生效版本在版本树中以徽标标识，可在版本行上「设为生效 / 取消生效」切换。
- 导入新版本或覆盖同版本不改变当前生效版本；时延分析使用当前生效版本的 matcher/stage 规则。

## 页面约定

- 左侧以“版本 -> 层级 -> 节点”树展示已导入内容。
- 主页面保留规则包导入和校验结果入口；节点内容不常驻占用页面区域。
- 单击树节点查看概要；双击节点打开编辑弹窗。
- 内容列表保持紧凑，展示当前层级的关键字段和引用状态。
- 导入反馈和完整性问题在右侧集中展示。

## 导入范围

一个规则包必须包含：

- `manifest.toml`：规则集标识、版本、格式和层级文件映射。
- `definitions.toml`：`scenarios`、`domains`、`applications`、`flows`、`processes`。
- `matchers.toml`：`log_matchers`。
- `stages.toml`：`stages`。

文件名由 `manifest.toml` 显式映射，不能仅依赖文件名猜测层级。系统还必须校验映射层级与文件内 TOML 节点一致。

## 主流程

1. 用户点击导入并选择一个完整 `.zip` 规则包。
2. 系统在压缩包根目录读取 `manifest.toml`，确认版本和层级文件映射。
3. 用户可在导入前自行使用外部 AI 检查规则包；该步骤不由项目调用或记录。
4. 系统读取所有声明文件，校验文件完整性、层级边界和关键跨层级引用。
5. 校验失败时，既有版本保持不变并展示拒绝原因。
6. 校验通过时：版本不存在则新增版本；同版本则整包覆盖。
7. 用户浏览版本树，双击节点可在弹窗内修改；修改后的内容必须重新校验并整体替换当前版本。
8. 用户在版本树中手动选择某个版本为「生效版本」；未设置生效版本时，时延分析提示先设置。

## 验收标准

- 规则包可通过 `manifest.toml` 无歧义定位版本与全部层级文件。
- 非 `.zip`、根目录缺少 `manifest.toml`、层级映射错误或关键引用错误时，均不改变已有版本。
- 导入新版本后，版本树可展示全部三层层级及节点数量。
- 再次导入同版本的合法规则包后，该版本的全部规则内容被新包替换，其他版本不受影响。
- 导入不存在版本的合法规则包后，系统自动新增该版本。
- 缺少文件、层级不匹配或引用不完整的规则包不能创建或覆盖版本。
- 双击节点可打开编辑弹窗；页面不保留常驻节点详情面板。
- 节点保存后，未编辑 TOML 文件的内容保持不变；已编辑文件保留原有注释、空白和未编辑项目的相对顺序。
- 未设置生效版本时，版本树无生效徽标，时延分析提示先设置生效版本。
- 设置生效版本后，仅该版本的 matcher/stage 规则参与时延分析，其余版本不参与。
- 导入新版本或覆盖同版本不自动改变生效版本；已有生效版本保持不变。
- 生效版本选择持久化，刷新页面后保持。

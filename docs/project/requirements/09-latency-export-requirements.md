# 时延分析 CSV 导出需求

## 需求列表

- REQ-LATENCY-EXPORT-001: 用户可以导出当前业务流程和请求筛选条件命中的时延分析结果。
- REQ-LATENCY-EXPORT-002: 导出文件采用单个 CSV，按关键日志时间戳、阶段时延明细、阶段汇总统计三个连续区域组织，区域之间保留一个空行。
- REQ-LATENCY-EXPORT-003: 前两个区域的第一列固定为“业务含义”，其后每列对应一个请求。
- REQ-LATENCY-EXPORT-004: 请求列表头使用系统请求 ID 与全局开始日志原始时间戳的组合，格式为 `<系统请求ID>(start=<原始开始时间戳>)`。
- REQ-LATENCY-EXPORT-005: 关键日志区域每行对应规则集中的一个 `log_matcher`，首列使用其 `business_meaning`，请求单元格使用命中原始日志中的原始时间戳文本。
- REQ-LATENCY-EXPORT-006: 阶段时延区域每行对应规则集中的一个 `stage`，首列使用其 `business_meaning`，请求单元格使用该请求的阶段耗时毫秒数。
- REQ-LATENCY-EXPORT-007: 阶段汇总统计区域包含“业务含义、样本数、平均值(ms)、P90(ms)、最大值(ms)”五列，每个阶段占一行。
- REQ-LATENCY-EXPORT-008: 某请求未命中关键日志或无法生成某阶段时，对应单元格留空。
- REQ-LATENCY-EXPORT-009: 导出不包含规则 ID、类型、应用 ID、进程 ID、原始日志正文或其它技术字段。
- REQ-LATENCY-EXPORT-010: CSV 使用 UTF-8 BOM 编码，使包含中文业务含义的文件可直接通过常用表格软件打开。
- REQ-LATENCY-EXPORT-011: CSV 只输出当前分析场景下有效且 `export_enabled=true` 的日志匹配器与阶段。

## 主流程

1. 用户选择分析场景和业务流程，并通过时间、结束结果或是否异常筛选请求列表。
2. 用户执行时延分析导出。
3. 系统按当前筛选结果确定请求列，并生成组合请求表头。
4. 系统按业务规则顺序输出每个关键日志匹配器命中的原始时间戳。
5. 系统按阶段顺序输出每个请求的阶段时延。
6. 系统在底部输出每个阶段的样本数、平均值、P90 和最大值。
7. 系统生成一个 CSV 文件供用户保存到本地。

## CSV 数据契约

## 验收标准

- 导出文件只包含一个 CSV，并按已确认的三个区域顺序输出。
- 每个筛选命中的请求在前两个区域中各占一列，两个区域的请求列顺序一致。
- 每个关键日志行输出原始时间戳，每个阶段行输出毫秒时延。
- 阶段统计位于时延明细下方，不追加到请求明细右侧。
- 除最左侧业务含义、请求数据和底部统计外，不出现其它业务或技术列。
- 未命中数据保持空单元格，不填入 `N/A` 或状态文本。
- 切换分析场景后，CSV 仅保留适用于该场景且允许导出的行。

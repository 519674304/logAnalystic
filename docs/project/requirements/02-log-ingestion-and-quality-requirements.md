# 日志读取与数据质量需求

> 本文因「整体载入内存 → 流式读取」的架构变更而修订。旧版「整批导入 + 内存合并 + 加载到可查询状态」语义作废；固定日志格式与解析字段不变。

## 需求列表

- REQ-INGEST-001: 用户选择一个本地日志目录；服务校验目录并发现候选 `.log` / `.txt` 文件，形成工作区。
- REQ-INGEST-002: 系统只接受 UTF-8 编码文件。
- REQ-INGEST-003: 工作区按文件身份去重，不允许重复文件身份。
- REQ-INGEST-004: 单个文件不可读或格式异常时跳过该文件并在结果中报告原因，不中断其余文件。
- REQ-INGEST-005: 行级解析失败不阻断读取；成功解析行继续参与搜索和分析。
- REQ-INGEST-006: 解析失败行不参与搜索、请求识别和时延分析，计入跳过/格式问题统计。
- REQ-INGEST-007: 逐文件流式读取，不建立完整日志对象数组；每个文件用固定大小缓冲区读取，跨块残行拼接。
- REQ-INGEST-008: 单行异常长时设置明确上限并报告格式问题，避免无界内存增长。
- REQ-INGEST-009: 工作区摘要展示文件数、总大小；不预扫描行数。

## 固定日志格式

首批假设日志已经是固定格式单行日志，示例：

```log
20675: 06-12 10:39:38.257 32033 32033 W A00010/com.huawei.hmos.aibase/WakeupManager: mainProcess dispatch wakeup request [undefined,]
```

解析字段：

| 字段 | 说明 |
| --- | --- |
| lineNo | 原始行号 |
| timestamp | 日志时间，格式示例 `06-12 10:39:38.257` |
| pid | 进程 ID |
| tid | 线程 ID |
| level | 日志级别 |
| appPrefix | 应用前缀，例如 `A00010` |
| packageName | 包名 |
| tag | 日志 tag |
| message | 日志消息主体 |
| raw | 原始日志行 |

## 主流程

1. 用户选择日志目录。
2. 服务校验目录、扫描候选文件、创建工作区并返回摘要。
3. 用户发起搜索后，服务逐文件流式读取并解析。
4. 系统记录解析成功行与失败行，失败不中断读取。
5. 搜索结束后返回结果、进度与跳过文件列表。

## 验收标准

- 给定 UTF-8 的 `.log` / `.txt` 目录，服务可创建工作区并返回摘要。
- 单个文件失败时不中断，跳过文件及其原因可见。
- 内存使用不随日志总大小线性增长（固定缓冲区）。
- 数 GB 日志保持有界内存，不因整体载入内存而阻塞。

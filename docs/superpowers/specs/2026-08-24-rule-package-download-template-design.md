# 可下载规则包模板设计

## 目标

在规则配置页面提供一个可直接下载、解压阅读、修改并重新导入的完整规则包 ZIP 模板。模板必须通过当前规则包校验，且不依赖用户阅读额外文档才能理解七个文件的作用和主要字段关系。

## 方案

采用仓库内维护的静态模板源文件，并在构建前生成固定名称的 ZIP 下载文件。

- 模板源目录：`docs/project/templates/rule-package-template/`
- 下载产物：`public/templates/rule-package-template.zip`
- 页面入口：规则配置工具栏中的次级按钮“下载导入模板”
- 导入入口保持现有“导入完整规则包”按钮不变

不在 Rust 后端动态生成模板，也不在浏览器中引入 ZIP 打包依赖。模板内容由源文件直接维护，便于代码审查、版本控制和用户解压阅读。

## 模板内容

ZIP 根目录固定包含：

1. `manifest.toml`
2. `scenarios.toml`
3. `topology.toml`
4. `matchers.toml`
5. `relations.toml`
6. `stages.toml`
7. `flow.toml`

模板使用一套最小但完整的可运行示例，包含分析场景、两个应用、进程、日志匹配器、关系、时延阶段和业务流程。所有 ID 唯一，所有 `_id` 和 `_ids` 引用均指向模板中存在的节点。

## 注释规范

- 每个文件顶部使用中文说明该层解决什么问题，以及它与其他层的关系。
- 每类元素前说明该元素用途、可否重复，以及 ID 被哪些字段引用。
- 关键字段使用相邻注释说明是否必填、值的含义和引用目标。
- `manifest.toml` 明确说明：`package.version` 已存在时整包覆盖，不存在时新增版本。
- 示例值使用容易识别的技术标识，展示结构，不承诺覆盖全部可选字段。
- 注释不引入当前导入器不支持的流程，例如激活、冻结、历史或备份。

## 下载流程

用户点击“下载导入模板”后，浏览器或 Tauri WebView 通过同源静态地址 `/templates/rule-package-template.zip` 下载文件，默认文件名为 `rule-package-template.zip`。下载不调用 Tauri 命令，不修改本地规则版本，也不触发导入。

用户解压并修改模板后，通过现有“导入完整规则包”选择 ZIP。版本新增或覆盖仍由 `manifest.toml` 中的 `package.version` 决定。

## 错误边界

- 下载按钮只负责下载，不负责检查用户后续修改的文件。
- 模板生成失败应使模板检查脚本失败，不能留下过期 ZIP。
- 模板本身必须通过 Rust `RulePackage::from_zip_bytes` 校验。
- 外部 AI 检查仍由用户在项目外执行，不加入页面或后端。

## 测试与验收

- 静态契约检查确认页面存在“下载导入模板”链接，并指向固定 ZIP 地址。
- 模板检查脚本确认七个文件齐全，文件位于 ZIP 根目录，且每个文件包含中文说明注释。
- Rust 测试读取下载产物并通过完整包解析和引用校验。
- `npm run build` 后，ZIP 存在于 `dist/templates/`。
- 手工冒烟确认按钮可下载，下载后的 ZIP 可直接导入。

## 非目标

- 不提供空白模板或多个模板版本。
- 不增加在线模板编辑器、向导或字段表单生成器。
- 不动态匹配当前已导入版本生成模板。
- 不增加版本激活、冻结、历史、备份或回滚。

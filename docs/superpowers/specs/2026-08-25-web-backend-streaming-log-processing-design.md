# Web 后端与流式日志处理设计

**日期：** 2026-08-25  
**状态：** 已确认，待实施计划  
**目标：** 在保留 React UI 的前提下，使应用脱离 Tauri，改为通过本机 Web API 处理真实日志目录，并能稳定处理数 GB 日志而不将其整体载入内存。

## 背景与目标

现有应用由 React 前端通过 Tauri `invoke` 调用 Rust command。浏览器环境没有 Tauri 桥接，已有回退逻辑只能搜索内置样例日志；这不能满足真实日志分析，也不适合包含数 GB 文件的日志目录。

本次改造提供一个独立的、本机运行的 Rust Web 服务。用户在普通浏览器中使用 React 页面，页面通过 HTTP 调用本机服务。日志数据始终留在用户机器，不上传到远端。

目标：

- 不启动 Tauri 也能使用日志搜索、保存查询、规则包、时延分析和 CSV 导出。
- 支持选择或输入本机日志目录，并处理多个日志文件。
- 日志读取、搜索、分析和导出均采用流式方式；内存使用不随日志总大小线性增长。
- 搜索和分析提供进度、结果上限与取消能力。
- 尽量复用既有 Rust domain、application 和 infrastructure 逻辑；Tauri 可暂时保留为兼容入口。

非目标：

- 不建设远程多用户服务、登录、云端日志上传或数据库集群。
- 不保证浏览器直接读取任意本机目录；目录访问由本机 Web 服务完成。
- 首期不引入全文索引数据库。重复扫描的优化在流式基础能力稳定后单独评估。

## 方案选择

比较过三种方案：

1. 纯浏览器流式读取：无需后端，但受浏览器目录访问、会话生命周期和大文件稳定性限制，不适合作为数 GB 日志的可靠路径。
2. 独立本机 Rust Web 服务：浏览器通过 HTTP 使用本机分析能力，复用 Rust 逻辑且能直接流式访问文件系统。
3. 远端服务：可集中处理，但增加部署、上传时间和日志数据安全成本。

采用方案 2。服务默认只监听 `127.0.0.1`，不暴露到局域网或公网。

## 架构

```text
React / Vite Web UI
        |
        | HTTP fetch
        v
Rust Web API（仅 127.0.0.1）
        |
        +-- 应用服务
        +-- 流式日志读取、搜索与时延聚合
        +-- 本地配置、规则包、CSV 导出
        |
        v
日志目录 / 本机应用数据目录
```

### 模块边界

- **Web API 适配层：** 参数校验、HTTP 状态码、任务状态与 DTO 转换；不实现业务规则。
- **应用服务：** 编排工作区、查询、规则包、保存查询和分析任务；与 HTTP、Tauri 解耦。
- **流式日志引擎：** 发现文件、按块读取、拼接跨块残行、解析、过滤、上下文提取与聚合。
- **基础设施：** 文件系统访问、应用数据目录、临时导出文件和配置存储。
- **React 前端：** 页面状态、参数输入、进度轮询、错误反馈、分页结果与下载；不读取完整日志内容。

现有 Tauri command 可在迁移期间继续作为适配层，调用同一应用服务。新 Web API 与 Tauri 不互相依赖。

## 工作区与 API

前端提交一个日志目录后，服务创建工作区。工作区保存目录、过滤的文件清单和摘要，不保存完整日志文本。后续搜索与分析都引用工作区 ID。

初始 API：

| 路径 | 职责 |
| --- | --- |
| `POST /api/workspaces` | 校验目录、扫描候选日志文件、创建工作区并返回摘要。 |
| `GET /api/workspaces/{id}` | 返回工作区状态、文件数和总大小。 |
| `POST /api/searches` | 创建搜索任务。 |
| `GET /api/searches/{id}` | 返回搜索进度、汇总和分页结果。 |
| `DELETE /api/searches/{id}` | 请求取消搜索任务。 |
| `POST /api/analyses/latency` | 创建时延分析任务。 |
| `GET /api/analyses/latency/{id}` | 返回分析进度和结果。 |
| `DELETE /api/analyses/latency/{id}` | 请求取消分析任务。 |
| `/api/saved-queries` | 保存查询的读取、新增、更新、删除。 |
| `/api/rule-packages` | 规则包导入、版本树读取与节点更新。 |
| `POST /api/exports` | 生成可下载的 CSV 导出。 |

接口响应统一使用现有 issue/error 结构的等价 HTTP DTO。搜索与分析任务返回 `total_bytes`、`scanned_bytes`、`files_total`、`files_scanned`、任务状态和可选的跳过文件列表。

## 流式日志处理

### 读取策略

- 逐文件处理，不同时打开大量日志文件。
- 每个文件使用固定大小缓冲区读取，初始实现可配置为 1–8 MiB。
- 每块按换行拆分；最后一条未结束的残余行只暂存该行并拼接至下一块。
- 单行异常长时设定明确上限并报告格式问题，避免无界内存增长。
- 解析失败的行可计入跳过/格式问题统计，不中断其他文件。

### 搜索策略

- 关键字和正则在读取时匹配，不建立完整日志对象数组。
- 仅保留命中项、所需上下文和有限的分页结果。默认最多保留前 1,000 条可展示命中，仍持续统计总匹配数。
- 上下文通过小型滑动窗口维护前文；后文在命中后仅保留请求数量的后续行。
- 搜索可取消；取消后停止读取并返回已完成的进度与取消状态。

### 时延分析与导出

- 时延分析在流式读取期间维护阶段聚合、计数、时间窗口与必要的关联状态，不持有全部原始日志。
- CSV 使用迭代器/写入流逐行生成，避免在内存中拼接完整文件。

## 前端行为

- Web 模式通过 `fetch` 调用 API，替换对 `__TAURI__` 的依赖。
- 用户可输入目录路径；如果运行环境支持本机文件选择辅助能力，可在后续提供选择目录入口，但不以浏览器目录权限作为核心依赖。
- 创建任务后前端轮询任务状态，展示扫描进度、当前文件和已匹配数量。
- 结果分页展示；服务端的结果上限和截断状态必须明确显示。
- 取消按钮调用对应的 `DELETE` API。
- 浏览器只持久化轻量 UI 偏好；保存查询与规则包由服务端写入本机应用数据目录。

## 错误处理与安全边界

- 服务只绑定回环地址。
- 只访问用户明确提供的目录；不主动扫描磁盘。
- 目录不存在、权限不足、无匹配文件、无效正则、规则包格式错误、任务不存在和结果超限都返回结构化错误与用户可理解的消息。
- 某个文件不可读或格式异常时，任务继续处理其余文件，并在完成结果中报告跳过文件及原因。
- 工作区和任务可设置过期时间与显式清理，防止状态无限增长。

## 验收与测试

单元与集成测试应覆盖：

- 缓冲区边界上的日志行拼接及超长行保护。
- 多文件搜索、关键字/正则、大小写和上下文结果。
- 多 GB 等价流式输入下的有界内存行为（通过受控测试读取器验证）。
- 取消任务、无效目录、权限错误、无效正则和单文件失败后继续处理。
- 结果分页、结果上限、进度统计和 CSV 流式导出。
- 时延聚合与规则包、保存查询 API。
- React 的 API 错误、进度、取消和分页展示。

验收标准：

- 在未安装或未启动 Tauri 的环境中，浏览器可完成完整使用流程。
- 30 MB 日志在目标机器上正常处理；数 GB 日志保持固定缓冲区和有限结果集，不因整体载入内存而阻塞。
- 用户可以观察进度、取消任务、识别被跳过文件和下载导出结果。
